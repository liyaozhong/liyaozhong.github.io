**Agent 框架深度分析总结与解释**
本文对构建可靠的 Agent 系统中的 Agent 框架概念进行了深入探讨。核心论点是，确保大型语言模型（LLM）在过程的每一步都能接收到适当的上下文，是该领域面临的主要挑战 。作者强调，这需要仔细管理输入到 LLM 的内容，并执行必要的步骤来生成相关信息。   

文章首先对关键术语进行了定义，对比了 OpenAI 对 Agent 的广泛定义与 Anthropic 更精确的区分，后者将 Agent 系统中的过程划分为“工作流”（LLM 和工具的预定义代码路径）和“Agent”（LLM 动态地指导其自身流程）。作者更倾向于 Anthropic 的定义，并指出大多数在生产环境中使用的“Agent 系统”实际上是工作流和 Agent 的组合。   

博客强调了为关键业务应用构建*可靠* Agent 的困难性。虽然创建原型可能相对容易，但实现一致的性能质量是一个巨大的挑战 。作者认为，Agent 性能不佳通常源于 LLM 的问题，而这些问题往往与提供给模型的不正确或不完整的上下文有关。   

为了应对这些挑战，文章介绍了 LangGraph，这是一个具有声明式和命令式 API 的编排框架，Agent 抽象建立在其之上 。LangGraph 被描述为一个事件驱动的框架，其中 Agent 系统被表示为节点（代表工作单元）和边（代表节点之间的转换）。这些节点和边本质上是 Python 或 TypeScript 代码，允许开发者同时使用声明式结构和命令式逻辑。LangGraph 还具备多项关键特性，包括内置的持久化功能（用于内存管理和容错）、对人机协作（human-in-the-loop）和人机在环（human-on-the-loop）模式的支持、流式传输能力，以及与 LangSmith 的无缝集成，后者是一个用于调试和监控 LangChain 应用的平台 。   

文章随后深入探讨了 Agent 框架的不同“风格”，并从以下几个维度进行了比较：
• **工作流 vs. Agent：** LangGraph 支持工作流、Agent 以及将两者结合使用的混合方法。作者认为这至关重要，因为大多数生产系统都需要这种灵活性 。文章讨论了工作流的预测性与 Agent 的自主性之间的权衡，以及框架需要具备“低门槛，高上限”的特性。   
• **声明式 vs. 非声明式：** 尽管 LangGraph 通常被描述为声明式的框架，但作者澄清说，它在节点和边中混合使用了声明式结构和命令式代码。此外，LangGraph 还支持替代的功能式和事件驱动的 API 。作者认为，许多其他的框架并非真正的声明式或命令式编排框架，而仅仅是 Agent 抽象。   
• **Agent 抽象：** 作者对许多 Agent 抽象的局限性表示担忧，这些抽象可能会掩盖控制传递给 LLM 的上下文这一关键方面。虽然承认这些抽象可以使入门更加容易，但它们可能不足以构建可靠的 Agent。LangGraph 的方法是在其较低级别的框架之上构建 Agent 抽象，从而允许用户在需要时“逃逸”到更细粒度的控制 。   
• **多 Agent：** 文章强调了复杂系统中多个 Agent 之间通信的重要性。作者认为，在多 Agent 场景中，工作流和 Agent 抽象的结合通常能提供最佳的可靠性 。   
博客文章还回答了关于 Agent 框架的一些常见问题：
• **框架的价值：** 框架可以提供有用的 Agent 抽象（尽管可能存在缺点）、短期和长期记忆解决方案、对人机协作和人机在环交互的支持、流式传输、调试和可观察性工具、容错以及优化功能 。作者强调，许多这些特性对 Agent 和工作流都有益。   
• **Agent vs. 工作流的未来：** 虽然承认工具调用 Agent 的性能可能会提高，但作者认为控制 LLM 的输入仍然至关重要。工作流可能仍然更简单、更便宜，并且更适合某些应用，而大多数生产系统将继续是混合的。作者还讨论了在高度专业化的模型中，简单的工具调用 Agent 可能就足够的情况 。   
• **对 OpenAI 看法的批评：** 作者对 OpenAI 如何定义 Agent 框架提出了异议，认为其依赖于错误的二分法，并混淆了不同的方面。作者认为 OpenAI 的观点忽略了上下文管理的核心挑战以及一个可靠的编排层所带来的价值 。   
• **Agent 框架的比较：** 作者提供了一个指向动态更新的电子表格的链接，该表格比较了各种 Agent 框架的不同维度，包括 LangChain、Agents SDK、Google 的 ADK、Crew AI 等 。   
总而言之，这篇博客文章重申，构建可靠的 Agent 系统的核心挑战是确保 LLM 在每一步都拥有正确的上下文。文章强调，Agent 系统包含工作流和 Agent，并且许多现有的框架主要是 Agent 抽象而不是全面的编排工具。虽然 Agent 抽象提供了一个简单的起点，但它们可能会阻碍对上下文的关键控制。作者将 LangGraph 定位为一个在其之上构建了 Agent 抽象的编排框架，旨在提供易用性和构建复杂、可靠的 Agent 系统所需的灵活性 。
