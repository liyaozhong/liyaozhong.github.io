## 一、主流模型微调技术概述

模型微调是指在预训练模型（Pre-trained Model）的基础上，利用特定数据集进一步训练，使其适应特定任务、领域、风格或指令。目前主流的微调技术可分为以下几类：

### 1. 全量微调 (Full Fine-Tuning)

- **做法**：更新预训练模型的所有参数。
- **优点**：性能可能最佳，因所有参数都参与适配。
- **缺点**：计算和存储成本高（需要大量 GPU 资源，每个任务需保存完整模型副本），易发生灾难性遗忘（丢失预训练时的通用知识）。

### 2. 参数高效微调 (Parameter-Efficient Fine-Tuning, PEFT)

- **核心思想**：固定大部分参数，仅训练或新增少量参数。
- **优点**：降低计算和存储需求，训练更快，易部署多版本，有时缓解灾难性遗忘。
- **主流方法**：
    - **Adapters**：在模型层间插入小型模块，仅训练这些模块。
    - **LoRA (Low-Rank Adaptation)**：通过低秩矩阵近似权重更新，仅训练低秩矩阵。
    - **QLoRA**：LoRA 的量化版本，进一步减少显存需求。
    - **(IA)^3**：通过缩放因子调整内部激活，参数极少。
    - **Prefix Tuning / P-Tuning / Prompt Tuning**：添加可训练向量，固定模型主体。

### 3. 指令微调 (Instruction Tuning / Supervised Fine-Tuning, SFT)

- **目标**：使模型理解并遵循自然语言指令。
- **做法**：使用 {指令, 回答} 或 {输入, 输出} 数据进行有监督训练。
- **关系**：Instruction Tuning 是 SFT 的一种，专注指令遵循能力，可用全量微调或 PEFT 实现。

### 4. 对齐微调 (Alignment Tuning)

- **目标**：使模型行为与人类期望和价值观对齐。
- **主流方法**：
    - **RLHF (Reinforcement Learning from Human Feedback)**：基于人类反馈的强化学习。
    - **DPO (Direct Preference Optimization)**：直接利用偏好数据优化。
    - **Constitutional AI**：AI 根据预定义原则生成偏好标签。

## 二、SFT（指令微调）的实现步骤

SFT 旨在让模型根据输入（指令或问题）生成期望输出（回答或完成），是构建基础能力的关键步骤。

### 步骤：

1. **准备数据集**
    1. **格式**：{输入/指令, 输出/回答} 对，如 `{"instruction": "什么是光合作用？", "output": "光合作用是植物利用光能将二氧化碳和水转化为葡萄糖和氧气的过程。"}`。
    2. **来源**：公开数据集（Alpaca、Dolly）或业务数据。
    3. **质量**：需清晰、多样、准确。
    4. **数量**：几百到几十万条，视任务而定。
2. **选择基础模型**
    1. 推荐强大预训练模型，如 Llama 2/3、Mistral、Qwen、Gemma（避免已 SFT 或 RLHF 的 Chat 模型）。
3. **选择微调方法**
    1. **PEFT**：如 LoRA 或 QLoRA，推荐高效。
    2. **全量微调**：资源充足时可选。
4. **配置训练环境**
    1. **硬件**：GPU。
    2. **软件**：Python + Hugging Face 库（transformers、datasets、peft、accelerate、bitsandbytes、trl）。
5. **编写训练脚本**
    1. 使用 Hugging Face Trainer 或 SFTTrainer。
    2. **关键参数**：
        - `model_name_or_path`：基础模型路径。
        - `dataset_name/train_file`：数据集路径。
        - `learning_rate`：如 1e-4。
        - `num_train_epochs`：1-5 轮。
        - `output financiar_dir`：保存路径。
    3. **LoRA 配置**：`r`（秩）、`lora_alpha`（缩放因子）、`target_modules`（目标层）。
6. **数据处理**
    1. Tokenize 数据，格式化为模型输入。
7. **开始训练**
    1. 运行脚本，监控损失 (Loss)。
8. **评估与迭代**
    1. 用验证集评估（ROUGE/BLEU 或主观评分），调整超参数或数据。
9. **保存与合并**
    1. PEFT 可保存 Adapter 权重并合并到基础模型。

### 工具推荐：

- Hugging Face 生态（Transformers + PEFT + TRL）。
- Llama Factory、Axolotl、vLLM。

## 三、RLHF（基于人类反馈的强化学习）的实现步骤

RLHF 在 SFT 后进行，通过人类偏好数据优化模型，使输出更符合细微期望。

### 经典流程（3 阶段）：

1. **阶段 1：训练 SFT 模型**
    1. 如上所述，生成初始策略模型 (Initial Policy Model)。
2. **阶段 2：训练奖励模型 (Reward Model, RM)**
    1. **目的**：判断回答“好坏”。
    2. **数据准备**：
        - 从提示集采样提示。
        - SFT 模型生成多个回答（2-4 个）。
        - 人类排序或选最佳，构建 {prompt, chosen_response, rejected_response} 数据。
    3. **训练**：
        - 输入：{prompt, response}。
        - 输出：标量分数。
        - 损失：Ranking Loss，使 chosen 分数高于 rejected。
3. **阶段 3：用强化学习优化 SFT 模型**
    1. **目的**：用 RM 奖励信号优化 Policy Model。
    2. **过程**：
        - 采样提示，Policy Model 生成回答。
        - RM 计算奖励 `reward = RM(prompt, response)`。
        - 用 PPO 算法更新参数，加入 KL 散度惩罚防止跑偏。
    3. **工具**：Hugging Face TRL、DeepSpeed-Chat。

### 挑战：

- 复杂性高，涉及多模型协调。
- 数据和计算成本高。
- PPO 超参数敏感，RM 可能偏差。

## 四、SFT、RLHF、DPO、PPO 对比

以下通过表格和详细解释对比四者：

### 对比表格

| **特性** | **SFT** | **RLHF** | **DPO** | **PPO** |
| --- | --- | --- | --- | --- |
| **主要目标** | 遵循指令、执行任务 | 符合人类偏好 (Helpful, Honest, Harmless) | 符合人类偏好 (替代 RLHF 的 RL) | 优化策略，最大化奖励 |
| **输入数据** | {指令, 输出} 对 | SFT 模型 + 偏好数据 + 提示集 | SFT 模型 + 偏好数据 | 状态、动作、奖励、旧策略 |
| **核心机制** | 有监督学习（交叉熵损失） | 三阶段：SFT + RM + PPO | 单阶段：偏好数据直接优化 | Actor-Critic RL + KL 约束 |
| **输出结果** | 指令遵循模型 | 对齐模型 | 对齐模型 | 更新策略 |
| **复杂度** | 低 | 非常高 | 中等 | 高 |
| **计算成本** | 低 (PEFT) | 非常高 | 中等 | 高 |
| **需要奖励模型** | 否 | 是 | 否 | 需要奖励信号 |
| **使用 RL** | 否 | 是 (PPO) | 否 | 是 (RL 算法) |
| **优点** | 简单有效 | 对齐效果强 | 简单稳定，成本低 | 稳定高效 RL 优化 |
| **缺点** | 无法优化模糊偏好 | 复杂、成本高、不稳定 | 依赖偏好数据质量 | 超参数敏感 |
| **角色** | 基础能力构建 | 对齐方法 | 对齐方法 (替代 RLHF 的 RL) | RLHF 第三阶段算法 |

### 详细解释：

- **SFT**：像教学生做题，给题目和答案，让模型模仿。简单直接，但无法处理模糊偏好。
- **RLHF**：三步走，先教模型基本技能 (SFT)，再训练“裁判” (RM) 判断好坏，最后用强化学习 (PPO) 优化。效果好但复杂。
- **DPO**：直接用偏好数据调整模型，跳过裁判和 RL，简单高效。
- **PPO**：RLHF 第三阶段的 RL 算法，稳定优化策略，但本身复杂。

## 五、RLHF 与 DPO 的核心区别（通俗例子）

假设我们要训练一个机器人厨师，让它做的宫保鸡丁更符合美食家口味，有数据：美食家喜欢“做法 A”（chosen），不喜欢“做法 B”（rejected）。

### RLHF：

- **做法**：
    - 训练一个“评论家”（RM），看美食家记录，学会给菜打分。
    - 让厨师做菜，评论家打分，用 PPO 指导厨师调整做法，奖励高就多做，低就避免。
- **特点**：间接通过“评论家”评分优化，复杂但细致。

### DPO：

- **做法**：
    - 直接告诉厨师：“美食家喜欢 A 不喜欢 B”，调整厨师倾向 A 避开 B。
- **特点**：跳过评论家，直接用偏好优化，简单直接。

### 区别：

- **RLHF**：像请助教学会评分再教学生，套娃式。
- **DPO**：像老师直接告诉学生哪个作业更好，少走弯路。

## 六、总结

- **主流微调**：全量微调、PEFT、SFT、对齐微调（RLHF、DPO）。
- **SFT**：基础步骤，简单教模型指令。
- **RLHF**：复杂对齐，效果强但成本高。
- **DPO**：简化对齐，高效有竞争力。

实际中，先 SFT 构建能力，再选 RLHF 或 DPO 优化偏好。
