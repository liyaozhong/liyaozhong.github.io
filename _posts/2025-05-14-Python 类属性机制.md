与许多静态语言（例如 Java、C++）不同，Python 的类属性并非强制在类定义中显式声明。在静态语言中，预先声明属性有助于编译器在编译阶段进行内存分配、类型检查和字节码生成。然而，Python 作为一种动态语言，遵循“动态绑定”的设计哲学，类的属性是在运行时通过对象赋值动态创建的。

## 一、Python 属性声明的动态性

在以下代码中，`self.name` 并非在类定义中预先声明，而是在 `__init__` 方法中于运行时赋值创建：

```python
class Person:
    def __init__(self, name):
        self.name = name
```

这种动态属性设计带来了以下特点：

- **灵活性**：可以根据运行时条件动态地为对象添加属性。
- **简洁性**：代码量相对减少，无需强制提前定义所有可能的字段。

不过，这也给 IDE 的静态分析带来挑战，有时可能导致因拼写错误或属性遗漏而引发的运行时错误。

## 二、Python 类属性的底层运作

### 2.1 属性的存储位置

- **类属性**：存储在类对象的 `__dict__` 属性中。
- **实例属性**：则存储在实例对象的 `__dict__` 属性中。

每个实例默认拥有一个独立的 `__dict__`，用于存储该对象的所有属性及其对应值。

### 2.2 动态添加属性的开销

由于实例属性可以通过 `obj.new_attr = value` 的方式随时添加，这会带来一些潜在问题：

- **内存结构难以预测**：与 C++ 等语言中对象大小固定的情况不同，Python 实例的内存占用在创建后仍可能变化。
- **`__dict__` 的内存占用**：每个实例的 `__dict__` 都是一个标准的 Python 字典，当存在大量实例时，如果每个字典都独立存储键（属性名），会造成一定的内存开销。

为了优化这个问题，Python 从 3.3 版本开始引入了“共享键字典”（shared-key dict）机制。

## 三、共享键字典机制详解

### 3.1 引入背景

在默认情况下，每个对象的 `__dict__` 都是一个完整的字典，其结构大致如下：

```python
p1.__dict__ = {'name': 'Alice', 'age': 30}
p2.__dict__ = {'name': 'Bob', 'age': 25}
```

当存在大量实例时，由于属性名（如 'name', 'age'）在每个实例的 `__dict__` 中都会重复存储，这可能导致内存空间的浪费。

### 3.2 优化思想

共享键字典机制的核心思想是：让不同实例共享同一份属性名结构（即字典的键），而每个实例仅存储各自的属性值。

例如：

```python
Shared Keys: ['name', 'age']
p1 (values) → ['Alice', 30]
p2 (values) → ['Bob', 25]
```

在底层实现中，启用了共享键字典的实例，其 `__dict__` 不再是一个标准的 Python 字典，而是包含以下两个部分：

- `ma_keys`：一个由类共享的属性名结构（key schema）。
- `ma_values`：一个实例独有的值数组，存储与 `ma_keys` 对应的属性值。

### 3.3 技术细节

底层的字典对象结构（简化表示）可能如下：

```c
// Simplified C struct representation
struct PyDictObject {
    // ... other fields ...
    PyDictKeysObject *ma_keys;   // 属性名结构 (共享)
    PyObject **ma_values;        // 属性值数组 (实例独有)
    // ... other fields ...
};
```

当访问 `p1.name` 时，Python 的大致步骤如下：

1. 在共享的 `ma_keys` 中查找属性名 `name` 的索引（例如，索引 0）。
2. 然后从实例 `p1` 的 `ma_values` 数组中取出索引 0 位置的值 "Alice"。

这种设计不仅节省了内存，还在一定程度上加快了属性的访问速度，因为键的查找可以在共享结构中进行。

### 3.4 值数组的本质

这个“值数组”并非 Python 层面上的 `list` 或 `tuple` 对象，而是在 C 语言层面实现的 `PyObject**` 指针数组。它是一种更为轻量、定长且高效的数据结构，专为这种场景优化。

### 3.5 限制条件

共享键字典机制并非无条件启用，其主要限制包括：

- **属性结构一致性**：只有当实例的属性名集合和顺序完全相同时，它们才会启用（或保持）共享键字典。
- **动态修改的后果**：如果某个实例在之后动态添加了一个新的属性（即共享键中不存在的属性），或者删除了一个属性，那么该实例的 `__dict__` 就会“退化”为普通的字典结构，不再共享键。

## 四、动态添加属性对共享结构的影响

当一个实例对象添加了共享键结构中不存在的新属性时，例如，假设 `p1` 和 `p2` 最初共享键 `['name']`：

```python
p2.age = 30 # p2 原本没有 age 属性
```

将会发生以下情况：

1. `p2` 的属性结构将不再与原共享键（以及 `p1` 的结构）一致。
2. `p2` 的 `__dict__` 会从共享键字典退化为标准的 Python 字典。
3. 此时，`p2` 原有的键和值会被复制到一个新的标准字典中，并添加新的 `age` 属性：

```python
p2.__dict__ == {'name': 'Bob', 'age': 30} # 假设 p2.name 是 'Bob'
```

4. 其他如 `p1` 这样的实例，只要其属性结构未发生改变，仍然会继续使用共享键字典，不受影响。

### 如何避免退化？

一种有效的避免不必要退化的策略是在类的 `__init__` 方法中预先定义所有可能会用到的属性，即使某些属性的初始值是 `None` 也没关系。这样可以确保实例在创建时就拥有统一的属性结构，从而更容易触发或维持共享键字典机制。

```python
class Person:
    def __init__(self, name, age=None, address=None):
        self.name = name
        self.age = age          # 即使为 None，也声明了该属性
        self.address = address  # 同上
```
